# Story E3-S2: Fraud Threshold Configuration Loader

**Epic:** E3 (Fraud Detection & Scoring)  
**Story ID:** E3-S2  
**Title:** Load fraud threshold configuration

---

## Description

The system loads versioned fraud rule configurations from a JSON/YAML file at startup. Each line of business (Motor, Health, Life) has its own rule set with fraud thresholds. Rules are versioned; when rules are updated, new versions are created without affecting in-flight claims (which use the version pinned at intake).

---

## Acceptance Criteria

1. **AC1:** Configuration file defines fraud rules for each LOB with:
   - Rule name (e.g., "claim_amount_outlier")
   - Predicate / operator (e.g., `claim_amount > threshold`)
   - Threshold value (numeric, policy-specific)
   - Weight (0–100)
   - Description

2. **AC2:** Configuration includes a fraud score threshold per LOB. Claims with score >= threshold are flagged for manual review.

3. **AC3:** Configuration is loaded at system startup and cached in memory (immutable at runtime per session).

4. **AC4:** Configuration is versioned with a version number, effective date, and created_by_admin_id. Multiple versions can exist in the database; the active version is marked as current.

5. **AC5:** If configuration file is missing or malformed, system raises ConfigurationError with detailed parsing error message.

6. **AC6:** Configuration updates are recorded as new versions in database without deleting old versions (append-only history for audit).
