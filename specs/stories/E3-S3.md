# Story E3-S3: Fraud Screening & Routing Endpoint

**Epic:** E3 (Fraud Detection & Scoring)  
**Story ID:** E3-S3  
**Title:** Create fraud screening endpoint

---

## Description

The system evaluates a claim using the deterministic fraud rule engine and produces a fraud score. The endpoint is called after document verification (claim state = UNDER_REVIEW) and routes the claim to manual review if flagged, or advances to assessment if passed. The fraud score and triggered rules are recorded immutably in the database.

---

## Acceptance Criteria

1. **AC1:** Endpoint `POST /api/claims/{claim_id}/evaluate-fraud` triggers fraud rule evaluation using the claim's pinned rule version.

2. **AC2:** On success, endpoint returns HTTP 200 with: `fraud_score` (0–1.0), `fraud_rules_triggered` (array), `is_flagged` (boolean), and evaluated_at timestamp.

3. **AC3:** A FraudScreeningResult record is created and persisted immutably with: `claim_id`, `rule_version_id`, `fraud_score`, `fraud_rules_triggered`, `is_flagged`, `evaluated_at`, and `evaluated_by_system` = true.

4. **AC4:** If `is_flagged` = true, claim state remains UNDER_REVIEW with internal status = FLAGGED_FOR_FRAUD_REVIEW. If `is_flagged` = false, state remains UNDER_REVIEW with internal status = PASSED_FRAUD_CHECK (no state transition yet).

5. **AC5:** If claim not found or not in UNDER_REVIEW state, endpoint returns HTTP 409 with error code `INVALID_CLAIM_STATE`.

6. **AC6:** If fraud rule version is not found, endpoint returns HTTP 500 with error code `FRAUD_RULES_NOT_AVAILABLE`.

7. **AC7:** Endpoint returns correlation ID in header `X-Correlation-ID` for audit tracing.
