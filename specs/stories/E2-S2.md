# Story E2-S2: Document Upload & Storage Endpoint

**Epic:** E2 (Document Management & Verification)  
**Story ID:** E2-S2  
**Title:** Create document upload endpoint

---

## Description

Claimants upload supporting documents (police reports, invoices, medical bills, death certificates) via multipart form upload. The endpoint stores documents, records metadata (file name, upload timestamp, claim ID, document type), and marks documents as pending verification. Documents are stored in a persistent location with immutable timestamps.

---

## Acceptance Criteria

1. **AC1:** Endpoint `POST /api/claims/{claim_id}/documents` accepts multipart form with:
   - `file` (binary blob)
   - `document_type` (enum: POLICE_FIR, REPAIR_INVOICE, HOSPITAL_BILL, DISCHARGE_SUMMARY, DEATH_CERTIFICATE)

2. **AC2:** On successful upload, endpoint returns HTTP 201 with document ID, file name, document type, `uploaded_at` timestamp, and status = PENDING_VERIFICATION.

3. **AC3:** Uploaded file is stored with immutable timestamp and unique document ID; file cannot be modified after upload.

4. **AC4:** Document record is created in database with: `claim_id`, `document_type`, `file_name`, `file_url`, `uploaded_at` (UTC, immutable), and `verified` = false.

5. **AC5:** If claim not found, endpoint returns HTTP 404 with error code `CLAIM_NOT_FOUND`.

6. **AC6:** If `document_type` is invalid (not in enum), endpoint returns HTTP 400 with error code `INVALID_DOCUMENT_TYPE`.

7. **AC7:** Endpoint returns correlation ID in header `X-Correlation-ID` for audit tracing.
