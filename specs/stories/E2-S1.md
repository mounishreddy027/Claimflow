# Story E2-S1: Document Checklist Definition Per LOB

**Epic:** E2 (Document Management & Verification)  
**Story ID:** E2-S1  
**Title:** Define document checklist rules per line of business

---

## Description

Each claim type (Motor, Health, Life) has a mandatory document checklist. The system loads these checklists from configuration at startup. Checklists define which document types are required for each LOB and are used to validate document completeness before transitioning a claim from FILED to UNDER_REVIEW.

---

## Acceptance Criteria

1. **AC1:** Configuration includes three checklist definitions:
   - **Motor:** `["POLICE_FIR", "REPAIR_INVOICE"]` (required)
   - **Health:** `["HOSPITAL_BILL", "DISCHARGE_SUMMARY"]` (required)
   - **Life:** `["DEATH_CERTIFICATE"]` (required)

2. **AC2:** Checklists are loaded from a configuration file (JSON/YAML) at system startup and cached in memory (immutable at runtime).

3. **AC3:** If a required document is missing from uploaded documents, the system can identify it and report the missing document type in a validation error.

4. **AC4:** Checklist configuration includes metadata: document type name, required boolean, description (e.g., "Police First Information Report for motor claims").

5. **AC5:** Configuration is versioned and timestamped; future updates create new versions without affecting in-flight claims.
