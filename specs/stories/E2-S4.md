# Story E2-S4: Verification Decision Submission Endpoint

**Epic:** E2 (Document Management & Verification)  
**Story ID:** E2-S4  
**Title:** Create verification decision submission endpoint

---

## Description

Claims Document Verifier staff reviews uploaded documents against the LOB-specific checklist and submits a verification decision per document: VERIFIED or REJECTED. If all required documents are verified, the claim transitions from FILED to UNDER_REVIEW. If any document is rejected, the adjuster is prompted to request missing or corrected documents.

---

## Acceptance Criteria

1. **AC1:** Endpoint `POST /api/claims/{claim_id}/verify-documents` accepts request body:
   ```json
   {
     "decisions": [
       {
         "document_id": "doc-uuid",
         "status": "VERIFIED|REJECTED",
         "reason_code": "ACCEPTABLE|UNREADABLE|INVALID_FORMAT"
       }
     ],
     "verified_by_adjuster_id": "user-uuid"
   }
   ```

2. **AC2:** On submission, endpoint validates that all required documents per claim LOB are either VERIFIED or have been marked REJECTED. If any required document is missing, endpoint returns HTTP 422 with error code `INCOMPLETE_DOCUMENT_SET`.

3. **AC3:** If all required documents are VERIFIED, claim state transitions from FILED to UNDER_REVIEW with reason code `DOCS_VERIFIED`.

4. **AC4:** Each document record is updated with: `verified` = true, `verified_by_adjuster_id`, `verified_at` (UTC, immutable), and the decision status.

5. **AC5:** Endpoint returns HTTP 200 with updated claim state and list of verification results.

6. **AC6:** If claim not found or already in non-FILED state, endpoint returns HTTP 409 with error code `INVALID_CLAIM_STATE`.

7. **AC7:** All verification decisions are immutable after submission; the endpoint includes correlation ID in header `X-Correlation-ID`.
