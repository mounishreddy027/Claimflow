# Story E1-S2: Claim Intake Endpoint (FNOL Filing)

**Epic:** E1 (Claims Intake & Policy Validation)  
**Story ID:** E1-S2  
**Title:** Create claim intake endpoint for FNOL filing

---

## Description

Claimants submit a First Notice of Loss (FNOL) via a REST endpoint. The endpoint accepts policy number, incident date, claim type, and initial incident description, creates a claim in FILED state, validates policy active status, and returns a claim ID. The claim is persisted with the policy rule version pinned at intake time (immutable for determinism).

---

## Acceptance Criteria

1. **AC1:** Endpoint `POST /api/claims/intake` accepts request body:
   ```json
   {
     "policy_number": "MOTOR-12345",
     "incident_date": "2026-10-04T10:00:00Z",
     "claim_type": "MOTOR|HEALTH|LIFE",
     "incident_description": "Vehicle collision on highway"
   }
   ```

2. **AC2:** On valid input, endpoint returns HTTP 201 with claim ID, policy ID, claim state (FILED), and a correlation ID for audit tracking.

3. **AC3:** If policy is not active on incident date (per E1-S1 validation), endpoint returns HTTP 422 with error code `POLICY_NOT_ACTIVE` and reason (e.g., `POLICY_EXPIRED` or `POLICY_NOT_EFFECTIVE`).

4. **AC4:** Claim is created in database with state = FILED, `created_at` = current UTC timestamp, and `policy_rule_version_id` pinned to the active fraud rule version at intake time.

5. **AC5:** If policy number is not found in repository, endpoint returns HTTP 404 with error code `POLICY_NOT_FOUND`.

6. **AC6:** Endpoint returns correlation ID in response header `X-Correlation-ID` for end-to-end audit tracing.
