# Story E5-S1: Immutable Payout Ledger Repository

**Epic:** E5 (Settlement & Immutable Payouts)  
**Story ID:** E5-S1  
**Title:** Create immutable payout ledger repository

---

## Description

The system maintains an append-only, write-once-read-many (WORM) repository of all settlement and payout records. Once a payout record is created, it cannot be modified or deleted (immutable for SOX/audit compliance). The repository enforces immutability through database constraints and application logic.

---

## Acceptance Criteria

1. **AC1:** Settlement table schema includes: `settlement_id` (PK, UUID), `claim_id` (FK), `payout_amount` (decimal), `payout_state` (enum: PENDING_DISBURSEMENT, DISBURSED, FAILED_RETRY), `approved_by_admin_id`, `approved_at` (immutable UTC timestamp), `disbursed_at` (nullable, immutable once set).

2. **AC2:** Once a settlement record is created, its `settlement_id`, `claim_id`, `payout_amount`, and `approved_at` cannot be modified or deleted.

3. **AC3:** Database enforces immutability via NOT NULL constraints on immutable fields and triggers/constraints that prevent UPDATE on those fields.

4. **AC4:** Application code prevents DELETE operations on settlement records; any attempt to delete raises ImmutabilityViolationException.

5. **AC5:** Settlement records are never soft-deleted; if a settlement is superseded (rare override scenario), a new settlement record is created with a separate entry in OverrideAuditLog.

6. **AC6:** Repository provides read-only queries by settlement_id, claim_id, or date range; no direct modification methods.
