# Story E7-S3: Admin Override Decision Endpoint

**Epic:** E7 (Admin, Audit & Compliance)  
**Story ID:** E7-S3  
**Title:** Create admin override decision endpoint

---

## Description

Admin staff access an endpoint to override an assessment decision (REJECT → APPROVE or APPROVE → REJECT). The endpoint calls E7-S1 (Decision Override Authority) to perform the override, records it immutably, and returns the updated claim state and settlement details (if applicable). The endpoint enforces admin-only access control.

---

## Acceptance Criteria

1. **AC1:** Endpoint `POST /api/claims/{claim_id}/override-decision` accepts request body:
   ```json
   {
     "override_decision": "APPROVE_REJECTED|REJECT_APPROVED",
     "reason_code": "LEGITIMATE_HIGH_VALUE|CLERICAL_ERROR|...",
     "justification_comment": "optional text explaining decision",
     "admin_actor_id": "user-uuid"
   }
   ```

2. **AC2:** Endpoint verifies user has ROLE_ADMIN. If not, returns HTTP 403 with error code `ADMIN_ROLE_REQUIRED`.

3. **AC3:** On success, endpoint calls E7-S1 (Decision Override Authority) and E5-S2 (Settlement Payout Generation) as needed.

4. **AC4:** Endpoint returns HTTP 200 with: updated claim state, new settlement details (if override was to APPROVE), and override audit log entry ID.

5. **AC5:** If claim not found, returns HTTP 404 with error code `CLAIM_NOT_FOUND`.

6. **AC6:** If claim already has an override entry, returns HTTP 409 with error code `CLAIM_ALREADY_OVERRIDDEN`.

7. **AC7:** Endpoint includes correlation ID in header `X-Correlation-ID`. All operations (override + settlement generation) share the same correlation ID for audit tracing.

8. **AC8:** Reason code and justification comment are preserved immutably in OverrideAuditLog.
