# Story E4-S3: Assessment Decision Submission Endpoint

**Epic:** E4 (Assessment & Adjudication)  
**Story ID:** E4-S3  
**Title:** Create assessment decision submission endpoint

---

## Description

Claims Assessor staff reviews an automated assessment (fraud score, coverage, payable amount) and submits an adjudication decision: AUTO_APPROVE, MANUAL_REVIEW, or REJECT. The decision is immutable and recorded in the Assessment table. The claim state transitions accordingly: AUTO_APPROVE → APPROVED, REJECT → REJECTED, MANUAL_REVIEW → remains UNDER_REVIEW for escalation.

---

## Acceptance Criteria

1. **AC1:** Endpoint `POST /api/claims/{claim_id}/assess` accepts request body:
   ```json
   {
     "decision": "AUTO_APPROVE|MANUAL_REVIEW|REJECT",
     "reason_code": "FULL_COVERAGE_APPROVED|FRAUD_THRESHOLD_EXCEEDED|...",
     "assessed_by_adjuster_id": "user-uuid"
   }
   ```

2. **AC2:** On submission, endpoint calls E4-S2 (Payout Calculation) internally to compute payable amount and includes it in the assessment record.

3. **AC3:** Assessment record is created immutably with: `claim_id`, `assessed_amount`, `payable_amount`, `deductible_applied`, `co_pay_applied`, `reason_code`, `assessed_by_adjuster_id`, `assessed_at` (UTC, immutable).

4. **AC4:** If decision = AUTO_APPROVE, claim state transitions to APPROVED.
5. **AC5:** If decision = REJECT, claim state transitions to REJECTED.
6. **AC6:** If decision = MANUAL_REVIEW, claim state remains UNDER_REVIEW with internal status = ESCALATED_REVIEW.

7. **AC7:** If claim not found or not in UNDER_REVIEW state, endpoint returns HTTP 409 with error code `INVALID_CLAIM_STATE`.

8. **AC8:** Endpoint returns HTTP 200 with updated assessment and claim state. Endpoint includes correlation ID in header `X-Correlation-ID`.
