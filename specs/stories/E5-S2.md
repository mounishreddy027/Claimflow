# Story E5-S2: Settlement Payout Generation Service

**Epic:** E5 (Settlement & Immutable Payouts)  
**Story ID:** E5-S2  
**Title:** Implement settlement payout generation service

---

## Description

The system generates a settlement payout record from an approved claim. The service verifies that the claim is in APPROVED state, retrieves the assessment (which includes the immutable payable_amount), and creates a Settlement record matching the assessment amount. The settlement is marked as PENDING_DISBURSEMENT initially (actual bank transfer is out of scope for MVP).

---

## Acceptance Criteria

1. **AC1:** Settlement service accepts a claim_id and optional admin override flag.

2. **AC2:** Service verifies claim state = APPROVED. If not, it raises InvalidClaimStateException.

3. **AC3:** Service retrieves the Assessment record for the claim and extracts `payable_amount` (immutable).

4. **AC4:** Service creates a Settlement record with: `settlement_id` (new UUID), `claim_id`, `payout_amount` = `payable_amount` (exact match, no modifications), `payout_state` = PENDING_DISBURSEMENT, `approved_by_admin_id`, `approved_at` = current UTC timestamp.

5. **AC5:** Settlement record is persisted immutably (via E5-S1 repository); service returns settlement object with all immutable fields.

6. **AC6:** If claim not found, service raises ClaimNotFoundError. If assessment not found for claim, service raises AssessmentNotFoundError.

7. **AC7:** Payout amount must exactly match assessment payable amount; no rounding or adjustment is allowed.
