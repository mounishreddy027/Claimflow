# Story E5-S3: Settlement Confirmation & Ledger Recording Endpoint

**Epic:** E5 (Settlement & Immutable Payouts)  
**Story ID:** E5-S3  
**Title:** Create settlement confirmation endpoint

---

## Description

Settlement Officer staff confirms a settlement by submitting a POST request with the claim ID and approval. The endpoint triggers payout generation (E5-S2), records the settlement immutably in the ledger, transitions the claim to SETTLED state, and returns confirmation details. This is the final step before payout disbursement.

---

## Acceptance Criteria

1. **AC1:** Endpoint `POST /api/claims/{claim_id}/settle` accepts request body:
   ```json
   {
     "approved_by_admin_id": "user-uuid",
     "settlement_notes": "optional notes"
   }
   ```

2. **AC2:** On submission, endpoint calls E5-S2 (Settlement Payout Generation Service) to create the settlement record.

3. **AC3:** Claim state transitions from APPROVED to SETTLED with reason code `SETTLEMENT_CONFIRMED`.

4. **AC4:** Settlement record is recorded immutably in E5-S1 (Immutable Payout Ledger). Settlement ID and payout amount are returned in response.

5. **AC5:** Endpoint returns HTTP 200 with settlement details: `settlement_id`, `claim_id`, `payout_amount`, `payout_state` = PENDING_DISBURSEMENT, `approved_at` timestamp.

6. **AC6:** If claim not in APPROVED state, endpoint returns HTTP 409 with error code `INVALID_CLAIM_STATE`.

7. **AC7:** If settlement already exists for claim, endpoint returns HTTP 409 with error code `SETTLEMENT_ALREADY_EXISTS`.

8. **AC8:** Endpoint includes correlation ID in header `X-Correlation-ID` for audit tracing.
