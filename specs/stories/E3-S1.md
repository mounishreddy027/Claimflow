# Story E3-S1: Deterministic Fraud Rule Engine

**Epic:** E3 (Fraud Detection & Scoring)  
**Story ID:** E3-S1  
**Title:** Implement deterministic fraud rule engine

---

## Description

A business rule engine evaluates claims against versioned, deterministic fraud rules (no ML, no subjective scoring). Rules are expressed as predicates over claim attributes (e.g., "claim_amount > 5 * policy_average_claim_amount" = high risk). The engine returns a fraud score (0–100) and a list of triggered rule names. The engine is versioned so that in-flight claims always use the rule version pinned at intake.

---

## Acceptance Criteria

1. **AC1:** Rule engine accepts a claim object and a versioned rule set. For each rule in the set, it evaluates a deterministic predicate and collects triggered rules and score.

2. **AC2:** Fraud score is calculated as: `score = sum(rule.weight for rule in triggered_rules)`, where each rule has a weight (0–100). Final score is clamped to [0, 100].

3. **AC3:** Rules are defined in configuration with: rule name, predicate (e.g., `claim_amount > threshold`), weight, and description.

4. **AC4:** Rule engine returns a result object with: `fraud_score` (decimal 0–1.0), `fraud_rules_triggered` (array of rule names), and `is_flagged` (boolean: true if score >= policy threshold).

5. **AC5:** Rule evaluation is deterministic and idempotent: same claim + same rule version always produces the same score.

6. **AC6:** Engine raises ValueError if rule version is not found or if claim data is missing required fields for rule evaluation.
