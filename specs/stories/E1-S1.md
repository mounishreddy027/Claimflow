# Story E1-S1: Policy Active Date Validation

**Epic:** E1 (Claims Intake & Policy Validation)  
**Story ID:** E1-S1  
**Title:** Implement policy active date validation rule

---

## Description

The system must validate that a claim's associated policy is in ACTIVE status on the date of the insurable incident. This is a foundational business rule (AC-02) that gates claim acceptance at intake. If the policy is expired, lapsed, or pending inception on the incident date, the system rejects the claim immediately with a PolicyNotActiveException.

---

## Acceptance Criteria

1. **AC1:** Given a policy with `effective_date` and `expiry_date`, when a claim is filed with an `incident_date`, the system checks that `effective_date <= incident_date <= expiry_date`. If true, the policy is ACTIVE.

2. **AC2:** Given a policy with `expiry_date` in the past, when a claim is filed with an `incident_date` after expiry, the system rejects the claim with a `PolicyNotActiveException` and HTTP 422 status, including the reason code `POLICY_EXPIRED`.

3. **AC3:** Given a policy with `effective_date` in the future, when a claim is filed with an `incident_date` before the effective date, the system rejects the claim with `PolicyNotActiveException` and reason code `POLICY_NOT_EFFECTIVE`.

4. **AC4:** Given a policy with NULL `expiry_date` (lifetime coverage), the policy is considered active indefinitely as long as `effective_date <= incident_date`.

5. **AC5:** The validation is deterministic and executed synchronously in the claim intake flow. Validation errors include the policy number, incident date, policy effective/expiry dates, and reason code in the error response.
