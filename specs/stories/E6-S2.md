# Story E6-S2: Parent Claim State Management for Reopened Claims

**Epic:** E6 (Dispute & Sub-Claim Management)  
**Story ID:** E6-S2  
**Title:** Manage parent claim state for reopened sub-claims

---

## Description

When a settled claim has an associated sub-claim (created via E6-S1), the system optionally updates the parent claim's state to REOPENED to signal that the claim has a linked dispute or reopen request in progress. The parent record remains immutable; only a status flag is updated to reflect the relationship. The UI uses this flag to display linked sub-claims to customers and staff.

---

## Acceptance Criteria

1. **AC1:** When a sub-claim is created for a SETTLED parent claim, the parent claim's status is optionally updated to REOPENED (state remains SETTLED, but status = REOPENED).

2. **AC2:** A query for related claims by claim_id returns: parent claim (SETTLED, status REOPENED) and all linked sub-claims (FILED/UNDER_REVIEW/etc.).

3. **AC3:** Parent claim record itself is immutable; only the status flag is updated to reflect reopened state.

4. **AC4:** Queries support filtering by parent_claim_id to retrieve all linked sub-claims for a parent.

5. **AC5:** Sub-claims inherit policy and rule versions from parent; they are independent claims flowing through the pipeline.

6. **AC6:** API endpoint `GET /api/claims/{claim_id}/linked-claims` returns parent and all related sub-claims with their states and reason codes.
