# Story E1-S3: Claim Status Query Endpoint

**Epic:** E1 (Claims Intake & Policy Validation)  
**Story ID:** E1-S3  
**Title:** Create claim status query endpoint

---

## Description

Claimants and internal staff query the status of an existing claim. The endpoint returns the current claim state, reason codes, missing documents (if in UNDER_REVIEW), payable amount (if approved), and a timeline of state transitions. The response respects role-based access control: customers see redacted data, internal staff see full details.

---

## Acceptance Criteria

1. **AC1:** Endpoint `GET /api/claims/{claim_id}` returns HTTP 200 with claim object including: `claim_id`, `claim_state`, `incident_date`, `policy_number`, `line_of_business`, `created_at`, and `reason_code` (if applicable).

2. **AC2:** If claim state is UNDER_REVIEW, response includes `missing_documents` array with required document types not yet verified (e.g., `["POLICE_FIR", "REPAIR_INVOICE"]`).

3. **AC3:** If claim state is APPROVED or SETTLED, response includes `payable_amount` (decimal with fixed-point precision, at least 2 decimal places).

4. **AC4:** If claim state is REJECTED, response includes `rejection_reason_code` (e.g., `POLICY_EXPIRED`, `FRAUD_THRESHOLD_EXCEEDED`, `COVERAGE_EXCLUDED`).

5. **AC5:** Response includes correlation ID in header `X-Correlation-ID` for audit tracing.

6. **AC6:** If claim not found, endpoint returns HTTP 404 with error code `CLAIM_NOT_FOUND`.

7. **AC7:** Customer role receives redacted incident description (`[REDACTED]`) and no access to fraud/assessment details; adjuster/admin roles see full details.
