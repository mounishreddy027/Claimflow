# Story E4-S1: Coverage Assessment Logic

**Epic:** E4 (Assessment & Adjudication)  
**Story ID:** E4-S1  
**Title:** Implement coverage assessment logic

---

## Description

The system evaluates claim coverage by checking policy terms against the incident. Coverage logic determines whether the claim type is covered under the policy, whether the incident falls within coverage period, and whether the incident is excluded by policy exclusions. The assessment service returns a coverage status and reason code.

---

## Acceptance Criteria

1. **AC1:** Coverage assessment accepts: policy object, claim object (claim_type, incident_date, incident_description).

2. **AC2:** Assessment checks:
   - Claim type (MOTOR, HEALTH, LIFE) is included in policy coverages
   - Incident date falls within policy effective/expiry dates (already validated in E1-S1)
   - Incident description does not match known exclusions in policy

3. **AC3:** Assessment returns: `is_covered` (boolean), `coverage_reason_code` (e.g., "FULL_COVERAGE", "PARTIAL_COVERAGE", "NOT_COVERED"), and details (e.g., covered amount, exclusion reason).

4. **AC4:** If coverage is denied, reason code includes: `CLAIM_TYPE_NOT_COVERED`, `INCIDENT_OUTSIDE_COVERAGE`, or `POLICY_EXCLUSION`.

5. **AC5:** Assessment is deterministic: same policy + same claim always produces same coverage decision.

6. **AC6:** Assessment service can accept multiple policy versions; it uses the pinned version from the claim.
