# Story E2-S3: Document Verification Queue Service

**Epic:** E2 (Document Management & Verification)  
**Story ID:** E2-S3  
**Title:** Create document verification queue service

---

## Description

The system provides a queue of claims pending document verification. Internal staff (Claims Document Verifier role) retrieves a list of claims with uploaded but unverified documents, indexed by priority (oldest claim first). The queue respects document checklist requirements per LOB and shows which documents are missing or pending review.

---

## Acceptance Criteria

1. **AC1:** Endpoint `GET /api/document-verification-queue` returns HTTP 200 with a list of claims awaiting document verification, sorted by `uploaded_at` oldest first.

2. **AC2:** Each queue entry includes: `claim_id`, `policy_number`, `line_of_business`, `uploaded_documents` (array of document types and verification status), and `missing_documents` (array of required document types not yet uploaded).

3. **AC3:** Endpoint respects pagination: supports query parameters `page` (default 1) and `limit` (default 20, max 100), returning `total_count` in response.

4. **AC4:** Response filters out claims in FILED state without any uploaded documents; only shows claims with at least one document uploaded or partially complete uploads.

5. **AC5:** Endpoint returns correlation ID in header `X-Correlation-ID` for audit tracing.

6. **AC6:** Claims are only included if they have state = FILED or UNDER_REVIEW and have at least one unverified document.
